# OI 重开模拟器 v0.3.1 更新说明

> 从 v0.3.0 → v0.3.1 · 主题：**存档保护与稳定性**

v0.3.0 引入的存档系统经受住了第一轮实战检验，也暴露出几个边界场景。本版本围绕「玩家的进度值得被认真对待」做了一轮系统性加固，同时将发行形态升级为单文件。

## 🛡️ 存档保护

- **覆盖前确认**
  存在未完成存档时，「开始游戏」会先展示该存档的进度（第几年几月、推进到第几个月），确认覆盖后才会进入新局——手滑不再付出整局代价。确认放弃旧档的瞬间即删除存档文件，杜绝反复覆盖写入的可能。
- **原子写入**
  自动存档改为「先写临时文件、校验通过后替换」的两段式落盘。写入途中断电或进程退出，旧存档完好无损。
- **损坏拦截与现场保护**
  读档时校验关键数据合法性（月份范围、学年/日历月一致性、属性边界等）；非法存档会被整体拒绝并保留当前游戏状态原样，绝不让半残数据混入对局。
- **比赛途中禁止落盘**
  自动存档只在月度行动阶段触发；比赛 / 考试流程中的状态不再可能被写进存档。
- **轻量进度探测**
  覆盖确认框显示的进度来自存档头部摘要，读取成本极低。

## ✨ 界面反馈

新增右上角**通知浮层**：重要增益与事件不再只默默写进日志，而是以带彩色侧条的通知条形式短暂弹出、自动淡出——

- **专题完成**：标题之外同时展示具体奖励（如「永久精通：比赛中该维度子问题的思考时间 −1」）
- **获得特质 / 成就达成 / 保送锁定 / 焦虑发作 / 病倒**：均会即时提醒

专题面板同步增强：按钮悬停即可预览该专题的完成奖励；进行中专题时其余按钮置灰；底部新增「已精通」徽章行，已到手的加成一目了然。

## 🔧 问题修复

- **修复：重开新游戏时上一局状态残留**
  不读取存档直接开始新游戏时，上一局的进行中专题、已获精通、细心对拍计数、熬夜与病倒状态未被清理；其中残留的专题起算月会让新一局的首次结算被误判「专题逾期」而扣除心态。现在所有单局状态在新局开始时统一归零。
  （新增回归测试完整覆盖此场景。）
- **修复：已精通的专题可在接口层被重复接受**
  此前仅靠界面隐藏已精通专题，模块接口本身不设防；现已在 `Topics::accept` 层面直接拒绝，杜绝任何形式的重复刷取。

## 📦 单文件发行

- MinGW 运行时（libstdc++ / libgcc / winpthread / mcfthread）全部静态链接，发行包从「exe + 4 个 DLL」精简为**单个 exe**，解压即玩，也不再出现因缺少 DLL 而无法启动的问题。
- 主程序体积 2.0 MB → 4.8 MB，为标准库静态链接的正常开销；发行包总体积反而更小。

## 🧪 质量基线

- 测试扩展至 **52 用例 / 349 断言**，全部通过；新增用例覆盖：存档阶段守卫、损坏存档现场保护、进度摘要解析、单局状态重置回归等。
